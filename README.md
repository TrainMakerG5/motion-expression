# Expression — AviUtl2向けJavaScriptエクスプレッション

AviUtl2のトラックバー項目にJavaScriptの式（エクスプレッション）を設定し、数値を計算するプラグイン・スクリプトの試作版です。
本体にドッキングできる常設パネルから式を編集でき、座標だけでなく「ぼかし」の強さなど、トラックバーで設定する各種エフェクトの数値を対象にできます。
内部では、QuickJS-ngによる計算処理とAviUtl2本体との接続処理を分離しています。

## 検証環境

- Windows x64
- AviUtl2 2.1.15（SDK 2026/10/24）
- Visual Studio 2022以降のC++開発環境、CMake 3.24以上、Ninja
- QuickJS-ng v0.17.0

## インストール（配布ZIP）

1. [Releases](https://github.com/TrainMakerG5/motion-expression/releases) から `Expression-v0.1.0-windows-x64.zip` を取得し、展開します。
2. AviUtl2を終了し、ZIP内の `Plugin/Expression` をAviUtl2の `data/Plugin/Expression` に、`Script/Expression` を `data/Script/Expression` にコピーします。`licenses` フォルダも含めて配置してください。
3. AviUtl2を起動し、追加したプラグイン・スクリプトの信頼確認を行います。
4. 本体のウィンドウ一覧から「JSエクスプレッション」を開きます。付属の `examples/Expression-demo.aup2` で動作を試せます。

README・LICENSEも展開先に保持してください。AviUtl2本体は同梱していません。以下は開発者向けのビルド手順です。

## ビルド

作業フォルダでPowerShellを開き、以下のコマンドを実行します。

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1
```

- `bootstrap.ps1`: SDKとQuickJS-ngを取得し、SHA-256ハッシュを確認します。
- `build.ps1`: x64 Release構成でビルドし、単体テストを実行した上で成果物を `dist` に配置します。
- `tools/aviutl2` に `lua.dll`・`luaJIT.dll` がある場合は、それぞれと実際の `.mod2`・`.anm2` を使った連携テストもあわせて実行します。
- CMakeは環境変数 `PATH`、またはVisual Studio付属のものを自動的に探します。

## 検証用AviUtl2への配置

あらかじめAviUtl2のZIP版を `tools/aviutl2` に展開してから実行します。

```powershell
./scripts/install-local.ps1
```

検証用本体の `data/Script/Expression` と `data/Plugin/Expression` にファイル一式を配置します。
AviUtl2本体を終了した状態で実行し、配置後に `tools/aviutl2/aviutl2.exe` を起動してください。
初回起動時は、追加したプラグイン・スクリプトの信頼確認ダイアログが表示されます。

## 式編集パネル（0.1.0）

### 基本的な使い方

1. 本体のウィンドウ一覧から「JSエクスプレッション」を表示します。
2. タイムラインでオブジェクトを選び、パネル上部の一覧から数値項目を選びます。
3. 式を入力し、「計算を確認」で現在時刻の計算結果を確認します。
4. 「適用」で対象のパラメーターに式を結び付けます。パネルは開いたまま引き続き操作できます。

パネルはタイムラインなどと同じ本体のウィンドウとして登録され、本体の配置機能で好きな位置にドッキングして使えます。
設定画面の数値項目を右クリックして「JSエクスプレッションを編集」を選ぶことでも、その項目を直接パネルに表示できます。
式が設定されている項目は、一覧の先頭に `[JS]` 付きで表示されます。
また、パネルのサイズに合わせてコード入力欄とボタンの配置が自動で切り替わります。

編集作業なしで試す場合は、ファイルを配置した検証用AviUtl2で `examples/Expression-demo.aup2` を開いてください。
X座標に `value + time * 60`、ぼかしの範囲に `value + time * 30` が設定されており、オブジェクトを選ぶとパネルの一覧から登録済みの式を確認・編集できます。

### 式の書き方

```js
value + Math.sin(time * 2) * 100
```

- `value`: 式を適用する前の元の数値
- `time`: オブジェクト開始位置からの経過秒数
- `frame`: オブジェクト基準のフレーム番号

これらはすべて読み取り専用です。最後に評価された式の数値がそのまま計算結果になります。

```js
const amplitude = 100;
const frequency = 2;
value + Math.sin(time * frequency) * amplitude;
```

- トップレベルでの `return` は使用しません。評価結果は有限の数値である必要があります。
- 「式を有効にする」のチェックを外して適用すると、式を保持したまま元の値（固定値・直線移動）を使用します。
- 「元設定に戻す」を押すと式の結び付けを解除し、編集済みの基準値を保ったまま元の移動方法へ戻します。

### 数値プレビューと未適用コードの保持

コード入力欄の上部には、編集カーソル位置に対応する数値プレビューが常時表示されます。

- **シーン / time**: 「シーン」は本体の表示に合わせた1始まりのフレーム番号、「time」はオブジェクト開始からの秒数です。
- **元の値 / 現在値**: 「元の値」は式を適用する前の値、「現在値」は保存済みの設定を本体側で評価した値です。
- **未適用の式**: コードや有効状態の編集中は「未適用の式」の計算結果も並べて表示されます。ここでは試算のみを行い、対象の設定は書き換えません。
- **自動更新**: 編集カーソルの移動やコード入力に連動し、約100ミリ秒間隔で更新されます。更新によって項目一覧や入力中のコードが書き換わることはありません。
- **範囲外・エラー表示**: 編集カーソルが対象オブジェクトの範囲外にある場合は現在値を表示せず、その旨を表示します。式の評価エラーもプレビュー内に表示されます。

※「未適用の式」に表示される数値はJavaScriptの生の計算結果です。適用後は、対象パラメーター側の範囲や精度の制限によって値が丸められる場合があります。

未適用の変更がある間は、誤って別の項目やオブジェクトへ選択を変えても、編集中の対象とコードがそのまま保持されます。
「適用」または「変更を破棄」を選んでから、次の項目へ移動してください。
なお、未適用のコードはプロジェクトファイルには保存されません。プロジェクトを保存・再読み込みする際は、先に「適用」を押して確定させてください。

### データの保存仕様と対応範囲

- 式は `.aup2` 内のプラグインデータとして保存され、対象パラメーター側には式IDが保存されます。
- 同じ式が付いたオブジェクトを複製しても、片方の式の編集がもう片方に影響することはありません。
- 編集のたびに新しい式IDを割り当て、変更前の式もプロジェクト内に残すことで、Undo（元に戻す）操作に対応しています。
- 初版では「固定値」および「加減速・時間制御・参照式を使わない直線移動」に対応しています。それ以外の移動方法が設定されている項目には適用せず、パネル上に理由を表示します。
- 色・文字列・チェックボックスの制御や、After EffectsのエクスプレッションAPI互換には対応していません。

## アニメーション効果版（旧試作：JS制御）

1. 図形やテキストをタイムラインに配置します。
2. アニメーション効果から、Expressionの「JS制御」を追加します。
3. 初期コードではオブジェクトが左右に揺れます（トラックバーAが振幅、Bが速さ）。
4. 「JavaScript」のテキスト欄を編集して動作を変更します。

### 書き方

```js
const amplitude = controls.a;
const speed = controls.b;

obj.x += Math.sin(time * speed) * amplitude;
obj.rotation += time * 30;
```

| 名前 | 意味 |
| --- | --- |
| `time` | オブジェクト開始からの経過秒数 |
| `frame` | オブジェクト基準の現在フレーム番号 |
| `controls.a`, `.b`, `.c` | エフェクト内のA・B・Cトラックバーの値 |
| `obj.x`, `.y`, `.z` | 相対座標（Luaの `obj.ox`・`oy`・`oz` に対応） |
| `obj.rotationX`, `.rotationY`, `.rotation` | X・Y・Z軸回転（単位：度） |
| `obj.scaleX`, `.scaleY`, `.scaleZ` | 各軸の拡大率（`1` が等倍） |
| `obj.opacity` | 不透明度（`0` 〜 `1`） |

`obj` の各プロパティは、このアニメーション効果に入った時点の値で初期化されます。
計算結果は描画時の値にのみ反映され、「標準描画」などの設定欄自体を書き換えるものではありません。
入力した式は、プロジェクト内のエフェクトのテキスト設定として保存されます。

構文としては `const`、`let`、関数、配列、条件分岐、`Math` などが使用できます（ブラウザーやNode.js固有のAPIは提供していません）。
`return` の戻り値は使われず、`obj` の各プロパティへ代入した値が最終的な描画に反映されます。

## 共通の制限事項

- 評価のたびに独立したJS実行環境を生成するため、前フレームの変数やグローバル変数は保持されません。
- 別時刻のキーフレーム参照、別オブジェクトの参照、After EffectsのAPI互換はありません。
- コード長は最大64 KiB、JSのメモリ上限は16 MiB、1回あたりの実行時間は約50 msで打ち切られます。
- オブジェクト単位の旧試作（JS制御）では、不透明度は `0` 〜 `1` の範囲で指定します。
- パラメーターごとの数値の範囲や精度は、対象トラックバー側の制限にも従います。
- 適用前の計算確認に加え、再生中に式の評価が失敗した場合はLuaエラーとして通知されます。エラー発生時に特定フレームの値へフォールバックする機能は未対応です。
- エラーメッセージには `expression.js` の位置情報が含まれる場合があります。旧試作（JS制御）では内部ラッパーの都合上、行番号が入力欄の見た目より2行多く表示されます。
- 1プロジェクトあたりの式履歴は最大4096件、保存データは最大16 MiBまでです。
- 別プロジェクトへのオブジェクトの持ち込みや、式IDのみを持つエイリアスファイルの別環境への持ち運びには対応していません。
- 実際の映像の目視確認および動画書き出し結果の一致については、別途確認が必要です。

## 自動検証

`build.ps1` では、JS式の評価・エラー処理・タイムアウト・保存形式の単体テストと、付属のLua/LuaJITを用いた連携テストを実行します。
AviUtl2実機を用いた自動検証は、以下のコマンドで実行できます。

```powershell
./scripts/test-host.ps1
```

このスクリプトは `tools/parameter-test` に検証用の別コピーを作成し、そのプロセスのみを起動・終了します。
自作の検証用ファイルに対する信頼確認のみを自動処理し、通常作業用に起動しているAviUtl2本体には干渉しません。

実機検証では、以下の項目を実際のホスト上で自動確認します。

- X座標および「ぼかし」の強さ（範囲）の式による制御
- 式の無効化と再有効化
- 組み込みパネルでの式の追加・編集・計算確認・適用・エラー表示
- 未適用コードの保持と破棄、パネルサイズ変更への追従
- 編集カーソル移動に連動した「現在値」「未適用の式」の自動プレビュー
- プロジェクトの保存と再読み込み

検証結果のログは `tools/parameter-test/host-check.log` に、そのまま開いて試せるデモプロジェクトは `tools/parameter-test/Expression-demo.aup2` に出力されます。
なお、実機検証用のプラグイン `ExpressionProbe.aux2` は配布用の `dist` フォルダには含まれません。
